## Перевірка звичайного PR після активації

Для PR у default branch очікуються два статуси:
- `agent-orchestrator/review` — незалежне AI-рев’ю та обов’язкові перевірки кандидата.
- `agent-orchestrator/human-release` — рішення про потребу в окремому людському дозволі.

Автор і рев’юер можуть використовувати одного провайдера, але працюють в окремих чистих контекстах.
Рев’юер не отримує історію автора й має доступ лише для читання.
Доказ рев’ю прив’язаний до точних base SHA та head SHA відкритого PR у цьому репозиторії.
Зміна кандидата або бази вимагає нового відповідного доказу; старий verdict не підтверджує нову пару SHA.
Звичайний кандидат із валідним схваленням і успішними перевірками може отримати обидва успішні статуси.
Для чутливих змін AI-рев’ю може пройти, а `human-release` залишиться pending.
Тоді людина з write/maintain/admin доступом явно запускає **Explicit human agent release** на default branch.
Потрібні номер PR, точні перевірені head/base SHA та рішення `approve`; дозвіл стосується лише цього кандидата.
Автор PR може дати цей дозвіл після незалежного AI-рев’ю; майбутні зміни автоматично не дозволяються.
Очікувані статуси слід звірити з фактичним запуском і налаштованими required checks перед оголошенням перевірки успішною.
Інструкції для агентів самі по собі не блокують довільні дії в UI; merge обмежують реально налаштовані правила GitHub.

### Налаштовані перевірки my-great-health-bot

- `project-validation`

Це назви обов’язкових перевірок із поточної `.agent-orchestrator.json`; успішність підтверджує лише фактичний запуск для точної пари SHA.
