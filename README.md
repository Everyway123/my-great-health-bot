# Пульс тіла 🫀

Персональний health-бот Андрія Сусленка: **нутриціолог + спортивний тренер +
коуч сну/відновлення/довголіття** в одному Telegram-боті. Виділений з Hermes
(life_OS) 2026-08-04.

**Принцип:** код МІРЯЄ, модель НАРАТИВІЗУЄ. Кожне агреговане число, яке коуч
називає — середні, тренди, відсотки виконання, регулярність сну, рекорди в залі,
динаміка маркерів — пораховане чистою тестованою функцією і передане моделі
текстом. Моделі заборонено рахувати самій, і їй нема чого рахувати.

## Що вміє

### Дані заходять самі
- ⌚ **Oura** — персональний токен або OAuth2, синк тричі на день + разовий бекфіл.
  Сон за фазами, HRV, пульс спокою, кроки, зони активності, стрес, SpO2, VO2max,
  тренування. Ідемпотентно: повторний синк фізично не може створити дубль
  (унікальний `dedup_key` з id документа Oura).
- 📸 **Фото їжі** → страва, ≈калорії/макроси, вердикт, запис у журнал
- 🧪 **Аналізи** (фото або PDF) → всі маркери в окрему таблицю `health_lab_marker`
  зі словником синонімів: «Вітамін D» / «25-OH» / «Vitamin D3» — один ряд, а не три
- 🧬 **ДНК-звіти** → постійні риси в профіль, фарбують усі подальші поради
- 🏋️ **Силові з підходами** — «присід 4×8×80, RPE 8» → таблиця сетів
- ✍️ **Текст без команд** — факт логується, питання отримує відповідь із даних

### Порахувати те, чого не рахує ніхто
- 😴 **Sleep Regularity Index** (`domain/sleep.ts`) — справжній SRI за Phillips
  et al.: відсоток хвилин, коли ти в тому самому стані через 24 години. Регулярність
  ритму передбачає смертність сильніше за тривалість сну, і майже жоден трекер
  її не показує. Плюс циркулярні середні відбою/підйому і розкид у хвилинах.
- 🎯 **Типізовані цілі + adherence** (`targets.ts`, `domain/adherence.ts`) —
  ціль це валідований рядок у БД, а не текст у профілі. Відсоток виконання
  рахується по процесу, з обрізанням перевиконання, щоб один великий показник
  не ховав зірваний.
- 🏋️ **Прогресія** (`domain/strength.ts`) — e1RM за Еплі, рекорди, подвійна
  прогресія: тримай вагу, доки всі підходи не дійдуть до верху діапазону, тоді +2.5 кг.
- 🚨 **Сигнали** (`domain/triggers.ts`) — HRV нижче базової на 20%, стрибок пульсу
  спокою, температурне відхилення, борг сну, «два пропуски поспіль», стрибок ваги,
  маркер поза нормою без переперевірки. Код вирішує, модель формулює.
- ⛑️ **Критичні значення** (`domain/safety.ts`) — панічні пороги лабораторій.
  Спрацьовують ЗАВЖДИ, повз рішення моделі: промпт можна переговорити, поріг ні.

### Поведінка
- **Прямий у фактах, автономний у рішеннях.** Факт називає як є, рішення лишає
  користувачу — доказова база коучингу каже, що на дистанції в роки це працює
  краще за тиск.
- **Плани як implementation intentions** — не «3 тренування», а «ср 18:30 — верх».
- **Правило «ніколи не пропускай двічі»** — реагує саме на другий пропуск.
- **Крони:** 06:20/13:20/22:20 — синк Oura; 07:45 — фокус дня; 14:00 — перевірка
  сигналів (мовчить, якщо в даних нічого); 20:45 — дайджест; неділя 17:00 —
  тижневий звіт + план; 1-ше число 11:00 — квартальний огляд.

## Архітектура

```
┌ L0 адаптери ─ telegram · oura (PAT/OAuth2, pull) ─────────────┐
├ L1 подіїї ─── hermes.health_log: immutable, source, dedup_key ┤
├ L2 похідне ── metrics · sleep · adherence · strength ·        │
│               triggers · labs · safety  (чисті, тестовані)    │
├ L3 розум ──── FAST sonnet-5 / PRIMARY opus-5 / DEEP opus-5,   │
│               forced tool use + prompt caching персони        │
└ L4 доставка ─ крони за часом + тригери за подіями ────────────┘
```

```
src/
  index.ts              boot: міграції, alert sink, 6 кронів, полінг
  bot.ts                команди + media + text + fb-callback
  coach.ts              збірка контексту, виклики моделі, персистенція
  models.ts             три рівні моделей і effort
  targets.ts            типізовані цілі + валідація
  labs.ts               маркери: синоніми, збереження, серії за роки
  stats.ts              статистика з журналу (чиста)
  db/migrations.ts      нумеровані міграції
  db/migrate.ts         раннер
  adapters/oura.ts      PAT + OAuth2, sync, backfill, ідемпотентність
  domain/metrics.ts     денні метрики + серіалізація
  domain/sleep.ts       SRI, циркулярні статистики, борг сну
  domain/adherence.ts   план проти факту
  domain/strength.ts    e1RM, PR, подвійна прогресія
  domain/triggers.ts    rule engine
  domain/safety.ts      критичні значення
  reason/schema.ts      контракт tool use
```

**База — ТА САМА, що в Hermes.** `hermes.health_log` не перестворювався: усе,
що було залоговано ще через Hermes, на місці. Схему тепер ведуть міграції
(`hermes.health_migration`), а не `create table if not exists` по модулях.

## Підключення Oura

Два режими; якщо заданий `OURA_TOKEN`, використовується він.

**Персональний токен (рекомендовано).** Документація Oura називає їх скасованими
з грудня 2025, але акаунти, які досі можуть їх видавати, працюють нормально —
і це один env var замість усієї OAuth-церемонії.

1. https://cloud.ouraring.com/personal-access-tokens → створити
2. У Railway: `OURA_TOKEN`
3. У боті: `/sync`, далі `/backfill` — вся історія з 2022-05-01

**OAuth2 (запасний).** Публічний сервер не потрібен: код переноситься руками
один раз.

1. Застосунок: https://cloud.ouraring.com/oauth/applications
2. У Railway: `OURA_CLIENT_ID`, `OURA_CLIENT_SECRET`, `OURA_REDIRECT_URI`
3. `/oura` → відкрий посилання → дозволь → скопіюй `code=` з адресного рядка →
   `/oura_code <код>` (живе 10 хвилин)

Далі токени оновлюються самі (Oura ротує refresh-токен на кожному обміні —
тому він зберігається в `hermes.oura_token`, а не в памʼяті процесу).

## Деплой

```bash
git clone https://github.com/Everyway123/my-great-health-bot
cd my-great-health-bot
./scripts/deploy.sh
```

Скрипт лінкує проєкт, створює сервіс, ставить змінні і деплоїть. Oura-змінні
додай окремо — вони не підтягуються з Hermes.

## Команди розробки

- `npm run dev` — локально з hot reload
- `npm run build` — компіляція TypeScript
- `npm test` — vitest (84 тести на чисті функції)

## Що далі

- **Webhooks Oura** замість pull — Oura їх рекомендує, дані приходять за ~30 с
  після синку застосунку. Потрібен відкритий HTTPS-порт.
- **Evals** — золотий набір фото їжі та бланків із очікуваною екстракцією,
  прогін перед деплоєм. Зараз кожна правка промпту непідконтрольна.
- **Квартальна батарея тестів** — сила хвату, талія, VO2max, sit-to-rise.
- **Бекфіл аналізів** із паперу/кабінету лабораторії.
